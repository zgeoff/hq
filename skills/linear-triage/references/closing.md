# closing, freeing and promoting issues

Step 5 of a pass, as `linear-triage` runs it.

## completion

An umbrella issue is complete only when every repo's box in its checklist is ticked. Besides the stale candidates, check for completion each issue you read in this pass, each In Review issue, and each In Progress issue whose every PR merged more than 24 hours ago, however recently it moved. Close an open issue as Done when a merged PR shows each acceptance item met and its change needs no deploy or live check, or when the condition its own text sets for closing has happened, and comment the evidence: the PR, or the issue that met it. When a deploy or live check may still be due, leave the issue to delivery, unless every PR on it merged more than 24 hours ago. Then run `scripts/release-deployed.sh <repo>#<n>…` with the last PR in each repo it touched, and close it only when each one shows `deployed: true` and every acceptance item has its evidence: comment each PR, release and pinned version from its output. This covers zgeoff/tools and zgeoff/noslop too, which have no production pin: a merge there is live once a published release of each package it changes contains it. An hq merge is live once the hq installed on this host was built from a commit that contains it. The script reads that commit from `hq version --json`, and shows `deployed: null` for a build from source or a dirty tree. A preview check is evidence for an item, not that it is live. Otherwise comment once which items remain and who owns each, and leave it to delivery. When the evidence covers only part of the acceptance, or the issue is only probably covered by another, flag it with your recommendation. Judge only the written acceptance: an extra the PR adds beyond it, such as a test the acceptance never asked for, is no reason to flag. A one-off left in Backlog by step 7 turns stale after 14 days with nothing new: close it as not reproduced, with a comment, and don't flag it. For one In Progress, look for its agent with `atc_sessions_list` (session names carry the issue ID) and for its PR with `gh search prs GEO-<n> --owner zgeoff`. If either moved in 3 days, it isn't stale. Otherwise give it `Needs Geoff` and a comment: "Stale: nothing has moved since <date>. Recommend <keep, relaunch, or close>, because <reason>."

## what a closed or merged blocker frees

Check what a closed or merged blocker frees. For each issue in this pass's list that is Done, each you closed in this pass, and each whose every PR has merged, get it with its relations and read the issues it blocks. Free nothing from a Done you didn't close until its acceptance shows evidence: a merged PR that says `Fixes GEO-<n>`, a completion comment, or a Design's or Investigation's record. With none, reopen it to its last state and comment why.

## promoting Backlog issues

Check each Backlog issue in this pass's list or freed by a closed or merged blocker, and on a full pass every Backlog issue, against the Ready criteria, blockers aside. Move one that meets them to Ready, and comment why: the blocker that closed or whose PRs merged, or the criteria it now meets. When one fails only on a missing section whose information it holds, write the section as step 4 says, then move it.
