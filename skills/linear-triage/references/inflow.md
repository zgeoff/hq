# inflow

Step 8 of a full pass, before you save the pass line: count the day's inflow, give each issue filed from inside a PR a second look, and post one line. The line counts filed against closed, splits planned design follow-ups from reactive issues, and flags a day on the reactive count. Each issue filed from inside a PR gets a second look: could that PR have fixed it? (decision D-inflow-line)

1. **Fetch.** Take the window as the 24 hours up to the pass's start. List team GEO's issues updated since the window's start, in every state, with the fields `id`, `title`, `createdAt`, `completedAt`, `canceledAt` and `description`, 250 at a time, and save every page as step 1 of the pass does. An issue filed or closed in the window was updated in it, so this one list holds both.
2. **Count.** Run `scripts/inflow.sh --since <window start> --until <pass start> <page files>`. It prints JSON: `filed` (created in the window), split into `planned`, the design follow-ups whose description starts `From design `, and `reactive`, the rest, such as bugs, flakes and review-tool gaps; `closed` (moved to Done, or to Canceled, which takes in Duplicate, in the window), `flag` (true when reactive is more than half of closed), and `fromPR`, each filed issue whose description names a PR, as `<owner>/<repo>#<n>`.
3. **Second look.** For each `fromPR` issue, read it and the PR with `gh pr view <n> --repo <owner>/<repo>`. Ask: could that PR have fixed it? It could when the fix is in that PR's repo and needs no choice the issue left open, whatever its size, as hq-private's `delivery-design.md` says under "An item stays unfixed only for one of two reasons".
   - It could: comment on the issue that the PR could have fixed it, and why, and count it. Close nothing here: the completion rules in `closing.md` close the issue once a merged PR shows its acceptance met, never as superseded.
   - It couldn't: change nothing.
4. **Report.** Post one line, with the flag in its text only on a flagged day: `hq news add --topic report --text "inflow <pass date>: <filed> filed (<planned> planned, <reactive> reactive), <closed> closed (Done or Canceled)<; flagged: reactive is more than half of closed>; <n> filed from a PR, <m> the PR could have fixed: <each ID with its PR, and "open" when the PR is still open>"`. Save the same line after the pass's "TRIAGE PASS at" line.
