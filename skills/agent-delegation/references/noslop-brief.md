# noslop brief

noslop reviews the PRs on every repo `hq noslop` lists, after the agent's own self-review. `z-review` runs it with `hq review` after the agent's FINAL note, as `pr-review` says, and the agent never runs it. For a repo `hq noslop` lists, put these lines in the delivery brief's `{{review_lines}}`:

```text
noslop checks the rules in these sections of the shared skills, so read them before you write code and check your diff against them in your self-review: code-style's Function naming (with The I/O rule and Data or resource), Type claims, Structure, Errors and logs, and Comments; testing's Principles and Boundaries; and docs-writing's Describe the system as it is now, Give each doc one job and each fact one owner, Procedures as numbered steps, and Formatting and links. After your FINAL note, noslop posts each finding on the PR as a review comment by `noslop-review[bot]` that holds `<!-- noslop:finding`. List them with `gh api repos/zgeoff/<repo>/pulls/<n>/comments --paginate --jq '.[] | select(.user.login == "noslop-review[bot]" and .in_reply_to_id == null and (.body | contains("<!-- noslop:finding"))) | {id, path, line, body}'`. Answer every finding in its own thread with `gh api repos/zgeoff/<repo>/pulls/<n>/comments/<comment id>/replies -f body='<answer>'`. A comment that lists the anchors and ids of several findings holds them all, and one reply gives every one the same answer: noslop has no form that answers them apart. Fix each finding it lists before you answer it `fixed <sha>`. When one of them is wrong, fix the rest, leave the thread unanswered, and name the wrong one in your final report. The answer's first line holds only `fixed <sha>` or `not-a-defect <reason>`, with nothing after the sha; put any explanation on the lines after it, or noslop ignores the answer. Never quote the text `<!-- noslop:` in a reply: hq and noslop take any comment that holds it for noslop's own, so they skip the reply and read its fix as unnamed. Push the fix before you answer `fixed <its sha>`: it counts once noslop's fix call confirms the fix at the PR's head; a finding noslop reports again stays open. Fix each finding in one commit, and squash the fix locally before you push. Each push gets a review of only the code it changed, so a late commit can bring a new finding: answer it like the others. A rebase or a merge of `main` is fine; noslop reviews the files whose net change moved. A finding with no line in the diff is an issue comment by the same bot: answer it with `gh api repos/zgeoff/<repo>/issues/<n>/comments -f body='<its 16-hex id> <answer>'`. Answer a finding `not-a-defect` only when it is wrong. When the finding quotes a skill rule, answer `not-a-defect` only by quoting, on the lines after, the text that shows the rule doesn't apply: the shared rule's own wording, or a line of this repo's project skill that the shared skill lets it hold. Each shared skill says what its project skill may do: code-style and testing let it only add, such as a project verb or a stricter rule, and docs-writing lets it win where the two disagree. Without such a quote, fix it. A finding you leave unfixed for reason 1 or 2 goes in your final report, as the finish line says: send your FINAL note again, and leave its thread unanswered. Never answer `accepted-risk`: that is my call. When every finding has its answer: after a fix push, send your FINAL note again; with no new commit, say so in your answer to the message that sent you the findings.
```

The first line names the sections that noslop's lenses cite. Its reuse check has no section, because only the reviewer applies it. When a lens cites another section, change that line.

`z-review` checks each item the final report leaves unfixed and files the ones whose reason holds, as `pr-review` says, then replies `deferred GEO-<n>` in its thread. It sends any other item back to the agent to fix in the PR.
