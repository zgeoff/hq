# noslop brief

noslop reviews the PRs on every repo `hq noslop` lists, after the agent's own self-review. The reviewing session runs it with `hq review` after the agent's FINAL note, as `pr-review` says; the agent never runs noslop. Paste these lines into the delivery brief's finish line, where it says "<The review lines from noslop-brief.md.>":

```text
noslop checks the rules in these sections of the shared skills, so read them before you write code and check your diff against them in your self-review: code-style's Function naming (with The I/O rule and Data or resource), Type claims, Structure, Errors and logs, and Comments; testing's Principles and Boundaries; and docs-writing's Describe the system as it is now, Give each doc one job and each fact one owner, Procedures as numbered steps, and Formatting and links. After your FINAL note, noslop posts each finding on the PR as a review comment by `noslop-review[bot]` that holds `<!-- noslop:finding`. List them with `gh api repos/zgeoff/<repo>/pulls/<n>/comments --paginate --jq '.[] | select(.user.login == "noslop-review[bot]" and .in_reply_to_id == null and (.body | contains("<!-- noslop:finding"))) | {id, path, line, body}'`. Answer every finding in its own thread with `gh api repos/zgeoff/<repo>/pulls/<n>/comments/<comment id>/replies -f body='<answer>'`. The answer's first line holds only `fixed <sha>` or `not-a-defect <reason>`, with nothing after the sha; put any explanation on the lines after it, or noslop ignores the answer. Never quote the text `<!-- noslop:` in a reply: hq and noslop take any comment that holds it for noslop's own, so they skip the reply and read its fix as unnamed. Push the fix before you answer `fixed <its sha>`: it counts when that commit changes any file of the PR and the next review no longer reports the finding. Fix each finding in one commit, and squash the fix locally before you push. After the PR's last review round, push only fixes. Code that no `fixed` answer names and no round read goes to a new PR, which you open at once under the same issue with "Contributes to"; it gets its own first review and needs no new issue. A fix stays in this PR: a `--fixes-only` check confirms each `fixed` answer only when a `fixed` answer names each commit since that round other than a merge, and each merge since then is a merge of `main`, or on a stack layer its parent branch, with no hand edit beyond its conflict resolutions, which noslop checks in that run. After the PR's first review, a rebase must keep each reviewed commit's patch: `--fixes-only` maps the reviewed head onto the rebased branch by patch id, and refuses when a rebase changed, dropped or reordered a reviewed commit, or when the branch holds a merge. Once you have merged `main` or a parent branch into it, keep merging rather than rebase. If your coordinator asks you to rebase a branch that holds such a merge, merge instead and say so in your answer. A finding with no line in the diff is an issue comment by the same bot: answer it with `gh api repos/zgeoff/<repo>/issues/<n>/comments -f body='<its 16-hex id> <answer>'`. Answer a finding `not-a-defect` only when it is wrong. When the finding quotes a skill rule, answer `not-a-defect` only by quoting, on the lines after, the text that shows the rule doesn't apply: the shared rule's own wording, or a line of this repo's project skill that the shared skill lets it hold. Each shared skill says what its project skill may do: code-style and testing let it only add, such as a project verb or a stricter rule, and docs-writing lets it win where the two disagree. Without such a quote, fix it. A finding you leave unfixed for reason 1 or 2 goes in your final report, as the finish line says: send your FINAL note again, and leave its thread unanswered. Never answer `accepted-risk`: that is my call. When every finding has its answer: after a fix push, send your FINAL note again; with no new commit, say so in your answer to the message that sent you the findings.
```

The sections in the first line are the ones noslop's lenses cite, as noslop#63's rule table maps them. Its reuse check is reviewer-only and has no section. When noslop's lenses cite another section, change that line.

`z-delivery` files each unfixed item the final report lists, as `wrap-up.md` says, and sends its number to `z-review`, which replies `deferred GEO-<n>` in its thread.
